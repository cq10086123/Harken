## 3. 最可能**运行时**出问题的地方（按风险排序）

### 🔴 3.1 `compute` 每文件开一个 isolate

`probeLocalTags` 每个文件调一次 `compute`。**`compute` 每次都新建并销毁一个 isolate。**

- 几十上百首：无感。
- 几千首：isolate 启动开销累积会很明显，扫描可能比预期慢很多。

**这不是我引入的** —— 上游 `tag_probe_service.dart:591` 也是每文件一次 `compute`。
但如果你的曲库很大，这是第一个该优化的点：改成常驻 isolate（`Isolate.spawn` + port）
或按批传路径列表。

**观察方法**：扫描时看进度回调的节奏。若「每 20 首」的节流明显跟不上，就是这里。

### 🔴 3.2 增量扫描依赖 `fileModifiedMs`

`LocalSongBuilder.shouldReprobe` 的判断是：

```dart
existing.fileModifiedMs != entry.fileModifiedMs  →  重读标签
```

**容易出问题的场景**：

| 场景 | 后果 |
| :--- | :--- |
| 某些文件系统 mtime 精度只有秒/2秒（FAT32、部分 NAS 挂载） | 同秒内改的文件不会被重读 |
| 从 Windows 拷到 Android 后 mtime 变了 | 全库重读一次（慢但不算错） |
| `fileModifiedMs` 为 null（stat 失败） | 每次扫描都重读 |

**验证方法**：扫一次 → 什么都不改 → 再扫一次。第二次的 `LocalScanSummary.reused`
应该等于 `scanned`，`updated` 应该为 0。如果第二次仍然全部重读，就是这里。

### 🟡 3.3 专辑封面的「第一张内嵌图」取决于扫描顺序

没有 `folder.jpg` 时，专辑封面取**同目录第一首能读到内嵌图**的歌。
「第一首」= `Directory.list` 的返回顺序，**在不同文件系统上不一致**。

已做的缓解：挑选结果不依赖顺序的部分（旁挂图按候选表 + 字典序）是稳定的，
且 `groupByDirectory` 用 `LinkedHashMap` 保持插入顺序。

**残留**：同一专辑里如果多首歌内嵌图**不同**，且没有旁挂图，两次扫描可能选到不同的专辑封面。
实际影响很小（同专辑内嵌图通常一样），但如果你看到专辑封面「偶尔变」，就是这里。
**建议**：整目录导入时在每个专辑目录放一张 `folder.jpg`，这条路径就完全确定了。

### 🟡 3.4 `ConflictAlgorithm.replace` 会整行替换

`SongDao.upsertSongs` 用的是 `replace`。所以标签有变化的歌在重扫时是**整行重写**。

对本地歌影响很小（`isCue`/`cueOffsetMs`/`codec`/`coverId`/`audioSpec` 本来就是 null/false），
但要知道两件事：

1. **`songs.isFavorite` 会被重置为 0**。已核实**当前没有任何代码 UPDATE 这一列**
   （收藏走独立的 `favorite_service`，按 song id 存），所以现在无害。
   如果将来收藏迁到这一列，重扫会清收藏 —— 到时候必须改成合并写。
2. **你在「歌曲详情」里手改的元数据，重扫会被标签值覆盖**。这是扫描器的正常语义
   （标签是真相源），但值得知道。

### 🟡 3.5 旁挂图直接引用原文件，不拷贝

`sidecarPath = '$dirPath/$sidecarName'` —— `localCoverPath` 存的是**用户自己那张
`folder.jpg` 的绝对路径**，没有拷进缓存。

- 好处：零额外空间，`LocalCoverStore` 的清理逻辑碰不到它（`isManagedPath` 正确返回 false）。
- 风险：用户删了/移了 `folder.jpg`，封面就断了，要重扫才恢复。
  表现是 `Image.file` 的 `errorBuilder` 触发 → 退回占位图（**不会崩**，这是我专门加的分支）。

### 🟢 3.6 一个仍然存在、但我没修的既存隐患

**`SongDao.fetchByIds` 不分批。**

```dart
final placeholders = List.filled(ids.length, '?').join(',');   // 全部塞进一条 IN
```

`upsertSongs` 有 500 分批（`song_dao.dart:16` 的 `_maxIdsPerQuery`），它没有。
SQLite 的 `SQLITE_MAX_VARIABLE_NUMBER` 有上限，**本地曲库几千首时一次传入就会撞**。
飞牛场景没暴露是因为它按页取，一次最多几十条。

我在 `LocalSourceProvider` 内部按 400 自己分批规避了，**没有改 `SongDao` 的既有方法**。
但那颗雷还在，将来任何调用方都可能踩。**建议单独修。**

## 4. 三端各自要注意什么

| 平台 | 注意 |
| :--- | :--- |
| **Windows** | ① 路径分隔符：`localSongId` 会把 `\` 归一为 `/`，`dart:io` 在 Windows 上两种都接受，但我没法在这里实测。② 大小写：ID 做了小写归一（`caseInsensitiveFileSystem` 对 `TargetPlatform.windows` 返回 true）。③ **没有 MediaStore**，所以只有目录扫描这条路 —— 这也是为什么必须自己找 `folder.jpg`。 |
| **Android** | ① 权限：`READ_MEDIA_AUDIO` 已在 Manifest（`:163`），**没有 `MANAGE_EXTERNAL_STORAGE`**。用 `file_picker` 选的目录能读，但**不能任意递归 `/sdcard`**。② 系统媒体库那条路（`photo_manager`）**还没实现**，现在只有自定义目录。 |
| **iOS** | 自定义目录需要 `UIDocumentPicker` + security-scoped bookmark，**这块完全没做**。现在 iOS 上 `includePaths` 里存的路径重启后很可能失效。 |

**`caseInsensitiveFileSystem` 的实现方式值得留意**：它用 `defaultTargetPlatform`
而不是 `Platform.isWindows`，因为单测里 `defaultTargetPlatform` 可以被
`debugDefaultTargetPlatformOverride` 覆盖，两个分支都能测到。
这跟仓库里 `playback_router.dart` 的既有做法一致。

## 6. 不用 UI 的临时验证法（备用）

> 现在已有 UI 入口（见 §0），这一节留作 UI 出问题时绕开它直接验证扫描链路的备用手段。

想在不写设置页的前提下端到端验证扫描链路，最快的办法是临时插一段调用。
比如在 `lib/main.dart` 的 `AudioSourceRegistry.instance.ensureLoaded();` 之后加：

```dart
// ⚠️ 临时验证用，验完删掉
final repo = LocalSourceRepository.instance;
await repo.upsert(const LocalSourceConfig(
  id: 'local-test',
  name: '测试',
  includePaths: ['/sdcard/Music'],   // Windows: 'C:/Music'
  readFullTagsOnScan: true,
  cacheArtwork: true,
));
final summary = await LocalSourceProvider().scanSource(
  (await repo.loadSources()).first,
  onProgress: (p) => debugPrint('扫描 ${p.dirsVisited}/${p.filesFound}'),
);
debugPrint('$summary');
```

`LocalScanSummary.toString()` 会打印全部七个计数，能一眼看出哪一步没通：

| 字段 | 期望 | 不对说明什么 |
| :--- | :--- | :--- |
| `scanned` | = 目录里音频文件数 | 0 → 路径不对 / 权限不够 / 扩展名不在名单 |
| `added` | 首次 = scanned | 0 但 scanned>0 → `upsertSongs` 失败，看 sqflite 日志 |
| `updated` | 首次 = 0 | 首次就 >0 → `shouldReprobe` 判断有问题 |
| `reused` | 第二次扫 = scanned | 第二次仍为 0 → **§3.2 的 mtime 问题** |
| `skipped` | 0（除非设了 minDurationMs） | — |
| `albumCoverApplied` | ≈ 无内嵌图的文件数 | 0 但目录有 `folder.jpg` → 旁挂图没收集到 |
| `markedDeleted` | 删掉一个文件后重扫 = 1 | 0 → `_markMissingDeleted` 没生效 |
